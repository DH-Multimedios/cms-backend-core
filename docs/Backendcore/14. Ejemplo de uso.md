

## 🧠 Escenario

Creación de un proyecto **CRM API** utilizando `@dh/backend-core`.

El objetivo es mostrar cómo el core resuelve la base y el proyecto solo implementa su lógica.

---

## 🚀 Paso 1 — Crear proyecto

- Se crea un nuevo proyecto NestJS
    
- El proyecto se versiona en un repositorio (ej: GitHub)
    
- Se instala el core desde el repositorio privado:
    

```bash
pnpm add git+ssh://git@github.com:tu-org/backend-core.git
```

👉 Cada proyecto es independiente y consume el core como dependencia desde GitHub

---

## 🧠 Nota (opcional para aclarar al equipo)

Más adelante se puede migrar a:

- npm privado (GitHub Packages, etc.)
    

Pero inicialmente:  
👉 **git+ssh es suficiente y más simple**

---


## ⚙️ Paso 2 — Configurar core

Se inicializa el core con la configuración básica:

- base de datos
    
- autenticación
    

👉 el sistema ya cuenta con:

- Users
    
- Auth
    
- Roles
    
- DB
    
- Swagger
    
- infraestructura base
    

---

## 🧩 Paso 3 — Crear módulo de negocio

Ejemplo: `ProductsModule`

Incluye:

- entidad Product
    
- CRUD de productos
    
- lógica de negocio
    

---

## 🔗 Paso 4 — Uso de funcionalidades del core

### 👤 Usuarios

- cada producto tiene `userId`
    
- relación con el creador
    

---

### 🗂️ Taxonomías

- productos usan categorías:
    

```id="example"
product_categories:
- productId
- taxonomyId
```

- se obtienen desde TaxonomyService
    

---

### 🖼️ Imágenes

- categorías pueden tener imagen
    
- TaxonomyService puede devolver imagen si se solicita
    

---

### 🔐 Permisos

- acceso controlado por permisos:
    

```id="perm"
products.create
products.update
```

---

## 🔄 Paso 5 — Resultado

El proyecto:

- no implementa auth
    
- no implementa users
    
- no implementa roles
    
- no implementa infraestructura base
    

👉 solo desarrolla lógica de negocio

---

## 🎯 Beneficio visible

- proyecto funcional en menos tiempo
    
- código más limpio
    
- menor complejidad inicial
    

---

## 🧩 Flujo completo

```id="flow"
Proyecto nuevo
   ↓
Instala core
   ↓
Configura core
   ↓
Agrega módulos propios
   ↓
Utiliza servicios del core
```

Un desarrollo donde:
