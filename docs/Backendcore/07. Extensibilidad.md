## 🧠 Enfoque

El core está diseñado para ser reutilizado sin modificaciones directas.  
Cada proyecto puede adaptar el comportamiento mediante extensión y configuración, manteniendo el core estable.

---

## 🧩 Principio clave

> El core no se modifica para casos específicos.  
> Las adaptaciones se realizan en el proyecto que lo consume.

---

## ⚙️ Formas de extensión

### 1. Sobrescritura de servicios

Los proyectos pueden reemplazar servicios del core mediante inyección de dependencias.

Ejemplos:

- customizar lógica de autenticación
    
- extender comportamiento de usuarios
    
- modificar validaciones
    

---

### 2. Extensión de módulos

Los proyectos pueden:

- agregar nuevos módulos propios
    
- reutilizar módulos del core
    
- combinar ambos sin conflictos
    

Ejemplo:

- `ProductsModule` usando `Users` y `Taxonomies`
    

---

### 3. Configuración del core

El core se adapta mediante configuración:

- parámetros de autenticación
    
- comportamiento de módulos
    
- activación/desactivación de features
    

---

### 4. Composición de funcionalidades

Los proyectos pueden combinar servicios del core para construir lógica de negocio.

Ejemplo:

- obtener categorías con imagen
    
- relacionar usuarios con taxonomías
    
- integrar archivos en entidades propias
    

---

### 5. Extensión de entidades

Los proyectos pueden:

- agregar entidades propias
    
- relacionarlas con entidades del core (ej: userId, taxonomyId)
    

Sin modificar las entidades base del core.

---

## 🔐 Control de límites

- El core no incluye lógica de negocio
    
- Los proyectos no deben modificar código del core
    
- Las extensiones se realizan siempre desde afuera
    

---

## 🎯 Beneficios

- Permite adaptar el sistema a distintos clientes
    
- Mantiene una base estable y consistente
    
- Reduce la necesidad de forks o duplicación de código
    
- Facilita el mantenimiento y evolución
    

---

## 🚀 Resultado esperado

Un sistema donde:

- el core evoluciona de forma controlada
    
- cada proyecto puede extender sin romper la base
    
- el equipo trabaja sobre una arquitectura común y flexible
