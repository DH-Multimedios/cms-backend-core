## ✅ Qué incluye el core

El core provee una base reutilizable para APIs en NestJS, compuesta por módulos independientes y utilidades comunes, sin lógica de negocio.

---

## 🔐 Identidad y acceso

- Autenticación basada en sesiones server-side
    
- Gestión de usuarios (entidad base mínima)
    
- Sistema de roles y permisos:
    
    - CRUD de roles
        
    - Roles base: `SuperAdmin` y `Admin`
        
    - Sistema de **permisos por módulo** (ej: `users.read`, `products.update`)
        
    - Asignación de permisos a roles
        
- Guards y decorators reutilizables
    

---

## ⚖️ Jerarquía y control

- Sistema de **peso por rol**:
    
    - Define jerarquía (ej: SuperAdmin > Admin)
        
    - Uso principal: visibilidad y organización (frontend)
        
    - Uso secundario: bypass controlado en backend para roles superiores
        
- Sistema de protección:
    
    - Flag `isProtected` para usuarios/roles críticos
        
    - Restricciones de edición/eliminación sobre entidades protegidas
        
    - Acceso limitado según jerarquía
        

---

## 📊 Auditoría y sistema

- Auditoría de acciones del sistema
    
- Logging estructurado
    
- Health checks para monitoreo
    

---

## 🧱 Infraestructura común

- Paginación estándar
    
- Formato de respuestas unificado
    
- Manejo centralizado de errores y excepciones
    
- DTOs base y validaciones
    
- Integración con Swagger
    
- Base de datos integrada (PostgreSQL + ORM)
---

## 🗂️ Taxonomías

- Sistema de categorías y etiquetas reutilizables
    
- Relación polimórfica
    
- Aplicable a cualquier módulo
    

---

## 📁 Files

- Módulo independiente
    
- CRUD de archivos
    
- Gestión de metadata
    
- Abstracción de almacenamiento
    

---

## 🖼️ Media

- Módulo independiente
    
- CRUD de recursos visuales (imágenes)
    
- Gestión de metadata específica
    

---

## ⚙️ Settings

- Configuración persistente del sistema
    
- Estructura clave/valor
    
- Acceso global desde los módulos
    

---

## 🔔 Notificaciones

- Sistema basado en eventos (emitters)
    
- Definición de contratos
    
- Sin implementación de proveedores específicos
    

---

## ❌ Qué no incluye

- Lógica de negocio (productos, pedidos, CRM, etc.)
    
- Customizaciones específicas por cliente
    
- Integraciones externas concretas (WhatsApp, pagos, etc.)
    
- Frontend o interfaces administrativas
    

---

## ⚖️ Criterio de inclusión

Una funcionalidad forma parte del core si:

- Es reutilizable en múltiples proyectos
    
- Es independiente del dominio de negocio
    
- Sirve como base para otros módulos
    

---

## 🧠 Regla del equipo

> Si una funcionalidad puede variar según el cliente, no forma parte del core.

---

## 🎯 Resultado esperado

Un core:

- Completo desde el inicio
    
- Modular y desacoplado
    
- Simple de usar
    
- Extensible sin modificar su base
    
- Preparado para construir módulos de negocio encima
